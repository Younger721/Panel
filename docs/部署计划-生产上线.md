### 2.1 必改的四行（不写就会去连 ES / Milvus / MinIO）

`application-dev.yml` 里这三个值是**写死的**（`keyword-backend: elasticsearch`、`vector-backend: milvus`、`object-store: minio`），
不用环境变量覆盖，启动后每次检索都会去连不存在的服务：不崩溃，但**检索超时、索引初始化失败、上传报错**。

```properties
PANEL_SEARCH_KEYWORD_BACKEND=memory
PANEL_SEARCH_VECTOR_BACKEND=memory
PANEL_OBJECT_STORE=local
PANEL_OBJECT_STORE_LOCAL_DIR=/opt/panel/data/knowledge
```

验证方式：启动日志里不出现 `ElasticsearchKeywordIndex` / `MilvusVectorIndex` / `MinioKnowledgeObjectStore`，
`ss -tuln` 里没有 9200/9202、19530、9000 的连接尝试。

## 3. 实施阶段（总计约 2 小时，从空机到可登录）

### Phase 0 · 安全基座（15 min，**动之前先做**）
1. 本地生成密钥对 `ssh-keygen -t ed25519 -f ~/.ssh/panel_lab`
2. 公钥写入服务器 `~/.ssh/authorized_keys`，验证密钥可登录
3. `/etc/ssh/sshd_config.d/99-hardening.conf`：`PasswordAuthentication no`、`PermitRootLogin prohibit-password`、`MaxAuthTries 3`
4. `apt install fail2ban`，`ufw default deny incoming` + `allow 22,80,443`
5. 记一次 `sshd -t` 校验后再 `systemctl reload ssh`（防锁死）

> 顺序很重要：先确认密钥能登，再关密码。否则这台机器就得去腾讯云 VNC 救。

### Phase 1 · 运行时（10 min，apt 版本已核实可用）
```bash
sudo apt update
sudo apt install -y openjdk-21-jre-headless nginx mysql-server redis-server
```
- `openjdk-21-jdk-headless 21.0.12` / `mysql-server 8.0.46` / `redis-server 7.0.15` / `nginx 1.24.0`
- **不装 Maven、不装 JDK 全量**：jar 在本地打好再传，服务器只留 JRE（省 300 MB + 10 分钟）

### Phase 2 · MySQL 初始化（10 min）

### Phase 7 · Nginx（10 min）

```nginx

    listen 80;
    server_name _;
    root /var/www/panel;
    index index.html;
    client_max_body_size 40m;          # 对齐 multipart 40MB

        try_files $uri $uri/ /index.html;   # SPA 路由回落

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;

```

## 5. 已知坑（提前规避）

1. **对象存储默认落 `/tmp`**：`panel.object-store.local-dir` 缺省是 `${java.io.tmpdir}/panel-knowledge`，不配就是重启即丢文件。
2. **内存索引不持久**：`PANEL_SEARCH_RECOVER_INDEX_ON_START=true` 让启动时按库内切片重建；否则检索全空，需手动调 `POST /api/v1/kb/documents/{id}/reindex`。
3. **`.env` 是相对 CWD 加载的**：`optional:file:../.env`，systemd 的 WorkingDirectory 写错就读不到，会静默用 `123456` 当管理员密码。
4. **SSE 被 Nginx 缓冲**：`proxy_buffering off` + `X-Accel-Buffering no` 缺一个，前端就是"回答完才一次性出现"。
5. **安全组是第二道门**：本机 ufw 开了 80 不等于能访问，腾讯云控制台安全组必须放行 80/443；境内节点用域名走 80/443 需 ICP 备案，纯 IP 直连也建议先确认。
6. **首次启动 4 分钟内别重启**：Flyway 建 32 表 + 平台管理员引导，中途打断会留半套 schema。
7. **swap 已有 1.9 G**，JVM 在 1024m 上限下不易 OOM；但若后来加了 ES/Milvus，先升配再谈。

## 6. 回滚方案

- 代码：`/opt/panel/app/panel-backend.jar` 保留上一版 `panel-backend.jar.bak`，`systemctl restart` 即回退

## 6.5 向量库轻量化选项（替代 Milvus）

Milvus 官方只有两种"轻"：**Milvus Lite**（嵌入式，`pip install milvus-lite`，走 pymilvus，约 100 万向量上限、**只支持 Python**，Windows 也不支持）和 **Zilliz Cloud Serverless**（云托管，有免费额度）。Java 服务直连 Lite 做不到，要挂 Python sidecar，不建议。

真正能在这台 3.7 G 机器上跑的方案，按"要不要新进程 / 要不要持久化"排：

| 方案 | 额外进程 | 内存 | 持久化 | 适配工作量 | 说明 |
|---|---|---|---|---|---|
| **内存索引（现成）** | 无 | 按数据量算，1024 维 float32 ≈ 4 KB/片 | ❌ 重启重建 | 0（已有 `PANEL_SEARCH_VECTOR_BACKEND=memory`） | 几万片以内检索毫秒级，暴力余弦足够 |
| **Lucene HNSW（JVM 内嵌）** | 无 | 索引驻留 ≈ 4 KB/片 + HNSW 图开销 | ✅ 落盘 | 新增 1 个 `VectorIndexPort` 实现，约 150 行 | 随 jar 走，零运维，单机最优解 |
| **Qdrant** | 1 个（Rust 单二进制/容器） | ~150–250 MB | ✅ | 新增 1 个实现（REST） | 有官方 Java client，运维极简 |
| **pgvector** | 1 个 PostgreSQL | ~150–300 MB | ✅ | 新增 1 个实现 + 一套 PG | 若肯引入 PG，顺手把关系库也统一 |
| **ES dense_vector** | 1 个 ES | 1–2 GB | ✅ | 关键词那路已用 ES，向量顺带 | 一份进程干两件事，等于免费；但 ES 本身吃内存 |
| **Redis Stack（向量）** | 复用现有 Redis 需换 redis-stack 镜像 | ~100 MB | ✅ | 新增 1 个实现 | apt 的 redis-server 7.0 没有 search 模块 |

关键点：`VectorIndexPort` 接口只有 `upsert / search / delete / deleteDocument` 四个方法，**换后端是单点替换**，改一个类 + 一个环境变量，业务代码零改动。

**先算账再选**：1024 维 float32 = 4 KB/片。10 万片 ≈ 400 MB 纯向量，加 HNSW 图约 1.5 倍。简历/题库场景通常几千到几万片 → **内存索引就够，连向量库都不用装**。

⚠️ **一个容易踩的点**：向量**不落库**（`kb_chunk` 只有 `text`，没有 embedding 列），索引重建必须重新调百炼 embedding。
- 解决 A（小改动，推荐）：加一张 `kb_chunk_embedding(chunk_key, model, vector MEDIUMBLOB)`，ingest 时顺手落库，重建时优先读库 → 重启重建零 API 成本、零等待（约 4 KB/片）。
- 解决 B：换成落盘的向量后端（Lucene HNSW / Qdrant / pgvector / Milvus）。

## 6.6 云托管选项（不想自建 ES / Milvus）

**先明确一件事**：向量化（embedding）发生在百炼 API，`KbIndexer:60` 和 `KbSearchService:154` 各自调 `embedding.embed(...)`；Milvus / 内存索引只负责**存和查**这些 1024 维向量。换后端不影响"有没有向量化"。

| 产品 | 类型 | 与现有代码的兼容性 | 改动量 |
|---|---|---|---|
| **Zilliz Cloud** | 托管 Milvus（官方） | ✅ 兼容 Milvus REST v2 —— 代码走的就是 `/v2/vectordb/*` | 换 `PANEL_MILVUS_URL` + **补一个 `Authorization: Bearer` 头**（现在没带认证） |
| **阿里云 Milvus 版** | 托管 Milvus | ✅ 同上 | 同上 |
| **腾讯云 ES** | 托管 Elasticsearch | ✅ ES 协议兼容 | 换 `PANEL_ES_URL` + 补 Basic Auth；⚠️ `analysis-smartcn` 插件要装，装不了把索引模板的 `smartcn_tokenizer` 换成 `ik_max_word` / `standard` |
| **阿里云 Elasticsearch** | 托管 ES | ✅ 同上 | 同上 |
| **Elastic Cloud** | 托管 ES | ✅ 同上 | 同上 |
| **腾讯云 VectorDB** | 自研向量库 | ❌ 不是 Milvus 协议 | 需新写一个 `VectorIndexPort` 实现（REST，约 100~150 行） |
| **阿里云 DashVector** | 自研向量库 | ❌ 同上 | 同上 |
| **Qdrant Cloud / Pinecone / Weaviate Cloud** | 通用向量云 | ❌ 同上 | 同上 |

要点：
