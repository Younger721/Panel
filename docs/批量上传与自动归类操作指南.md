# 批量上传面试题 / 八股并自动归类

## 1. 先决定放哪个知识库

- 面试题：`面试题库`（`kind=QUESTION_BANK`）
- 八股/技术文档：`技术文档`（`kind=TECH_DOC`）

题和八股可以分两个 KB，也可以放同一个 KB；同一个目录树可以同时挂知识点和题目。

## 2. 推荐的 Markdown 格式

题库按“题目 + 答案”解析，最稳的是 `Q数字:` / `A数字:`：

```markdown
# Java

## Java1

Q1: HashMap 的底层数据结构是什么？
A1: JDK 8 使用数组 + 链表 + 红黑树，链表长度到 8 且数组容量到 64 时转红黑树。

Q2: ConcurrentHashMap 如何保证线程安全？
A2: JDK 8 用 CAS + synchronized 锁桶头节点，扩容时多线程协助迁移。
```

也支持：

- `1. 问题` + 下一段答案
- `问：...` / `答：...`
- 标题本身就是问题，正文是答案

一个文档最多解析 500 题；100 题/文档没问题。所有文件必须是 UTF-8 的 `.md` / `.markdown`。

## 3. 建目录（两种方式）

### 方式 A：想要固定名字，先手动建

比如：

```text
Java
  Java1
  Java2
八股
  Redis
  MySQL
```

先建好再上传，LLM 会优先把题目归到这些已有目录，名字完全按你建的来。

### 方式 B：完全交给 LLM 建

不建目录直接上传也可以。归类时 LLM 会按题目内容给出稳定主题路径，例如：

```text
Java
  集合
  并发
Redis
  缓存
  数据结构
```

系统自动创建缺失的 1~3 级目录。LLM 建的是语义主题名，不保证一定叫 `Java1`；要固定叫 `Java1` 就用方式 A 预建。

## 4. 批量上传

1. 进入知识库详情页
2. 点右上角「上传文档」
3. 文件选择框里 **按住 Ctrl/Shift 多选 20 个 md**
4. 确认后前端会逐个上传，后端最多 4 个文档并发解析/归类

上传接口立即返回，文档状态会依次经过：

```text
UPLOADING → PARSING → CHUNKED → INDEXING → READY
```

归类在 `CHUNKED` 阶段完成，100 题大约需要 10 次模型批量调用；20 个文档要等所有文档都变成 `READY`。

## 5. 自动分类规则

- 题库：**只按题目归类**，不按来源文档的 chunk 归类，避免目录树被文档章节名污染
- 技术文档/八股：按 chunk 归类
- 优先复用已有目录
- 没有合适目录时，LLM 给出 `path`，系统自动建目录
- 最多 3 级
- 置信度低于 0.72 的留在「未分类」，可在目录页点「自动归类」重跑

## 6. 查看

进入知识库 →「知识目录」：

- 点父节点：右侧按一级子目录分组展示
- 点子节点：右侧只展示该子目录内容
- 点卡片标题或「查看详情」：右侧抽屉直接看完整题目/答案或 chunk 正文

## 7. 常见问题

**上传后目录是空的？**

先确认文档状态是 `READY`；如果是题库，确认 Markdown 里确实能解析出 `Q:`/`A:` 或编号题目。解析不出题目时，题库会退回按 chunk 归类。

**为什么多了一个 `mysql` 和 `MySQL`？**

LLM 自动建目录时可能产生大小写/层级不一致。固定目录名请先手动建树，再上传；已有目录会被优先复用。

**20 个文档会不会很慢？**

会受模型调用速度影响。每个文档的题目按 10 条一批调用，文档之间 4 路并发；建议一次 20 个以内，等 `READY` 后再看目录。
