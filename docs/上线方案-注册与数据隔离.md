# 上线方案（一）：账号注册与用户数据隔离

> 目标：项目对外可用前，做到「能自助注册」「垃圾注册挡得住且不花钱」「简历 / 面试 / 题库三类数据互相看不见」。
> 迁移脚本：[V11__account_and_data_isolation.sql](../backend/src/main/resources/db/migration/V11__account_and_data_isolation.sql)
> 部署与升级：[部署与升级-运行手册](部署与升级-运行手册.md)

## 0. 结论先行

| 事项 | 结论 |
|---|---|
| 注册形态 | 邮箱 + 密码自助注册，一人一个「个人租户」，角色 `CANDIDATE` |
| 免费防滥用 | 邮箱验证码（免费 SMTP）+ 一次性邮箱黑名单 + IP/邮箱/设备限流 + 蜜罐 + 可选邀请码；有域名再加 Cloudflare Turnstile（免费） |
| 数据隔离 | 三张表加 `owner_user_id`，服务层统一 `OwnershipGuard`，越权一律 **404** |
| 现状最危险的洞 | **简历按内容哈希去重是全局的**：别人上传一份同内容文件，接口直接把**别人的简历记录**返回给你 |
| 迁移方式 | 只加列/加索引/加表，旧 jar 仍能启动（可蓝绿） |

## 2. 账号体系设计

### 2.1 账号模型：一人一个「个人租户」

为什么不是"单租户 + 靠 owner 字段"：`CurrentActor` 强制非平台角色带租户，配额、限流、AI 用量都按租户算。复用租户机制，等于**免费得到按用户隔离的配额与限流作用域**。

注册一次写六样东西（同一事务）：

```
sys_tenant                     code = p-<8位大写base32>，name = "<displayName> 的空间"
sys_user                       tenant_id = 上面的租户，角色 CANDIDATE，email_verified_at = NULL
sys_user_role                  CANDIDATE
sys_tenant_quota               defaults（由 TenantQuotaProvisioningContributor 自动写）
sys_tenant_settings            defaults（TenantSettingsProvisioningContributor）
kb_base                        code = u<userId>-personal，kind = QUESTION_BANK，owner_user_id = userId
```

个人题库在注册时建，用户登录后「练习」页立刻可用，不需要先手动建库。

### 2.2 注册时序

```
浏览器               后端                                 外部
  │ POST /auth/signup   │                                    │
  ├────────────────────>│ 1 蜜罐字段 / elapsed < 1.5s → 直接 201 丢弃
  │                     │ 2 Turnstile siteverify（可选） ─────> Cloudflare
  │                     │ 3 Redis 限流：ip /24 5·h, 20·d；全局 300·d
  │                     │ 4 邮箱归一化 + 一次性邮箱域名黑名单
  │                     │ 5 邀请码（mode=invite 时）
  │                     │ 6 建租户 + 用户 + 个人题库（事务）
  │                     │ 7 写 sys_email_verification，异步发码 ─> SMTP
  │<── 201 + token ─────┤ 8 直接签发 access/refresh（不阻塞首次体验）
  │ POST /auth/verify   │
  ├────────────────────>│ 校验 code（10 分钟、5 次尝试、一次性）
```

关键取舍：

- **重复邮箱不报 409**：一律返回「若邮箱可用将收到邮件」，同时给已存在账号发一封「你已有账号，请直接登录」。否则接口就是个账号枚举器，也给刷号的人省事。
- **不验证也能用，但受限**：未验证邮箱 24 小时内 AI 调用 ≤ 20 次、上传 ≤ 2 份、不能改邮箱/密码。想深耕就把 `panel.signup.require-verified=true` 打开，未验证直接 403。
- 密码：≥ 10 位、含字母与数字、禁 top 2000 弱口令（本地词表），BCrypt 已有。

### 2.3 免费防滥用组合（按性价比排序）

| # | 手段 | 免费额度 | 挡什么 | 接入成本 |
|---|---|---|---|---|
| 1 | **邮箱验证码** | QQ 邮箱 SMTP 免费（单账号日约 50–100 封）；163 约 200 封/日；Brevo 300 封/日、Resend 100 封/日 | 批量注册的 90%（要能收信） | 1 个依赖 + 30 行发送逻辑 |
| 2 | **一次性邮箱域名黑名单** | 开源域名表（约 4000 条），放 `classpath:disposable-domains.txt` | temp-mail / 10minute 类 | 10 行 |
| 3 | **邮箱归一化** | 免费 | 同人 `a+x@gmail.com` / `a.x@gmail.com` 多开 | 5 行 |
| 4 | **IP 限流** | Redis 现成 | 同 IP 脚本注册 | 已有 `TenantRateLimitFilter` 的结构，复制成 `AuthRateLimitFilter` 即可 |
| 5 | **蜜罐 + 提交耗时** | 免费 | 低级脚本 | 5 行 |
| 6 | **Turnstile** | 免费、无调用上限 | 自动化注册 | 前端 1 个 script + 后端 1 次 siteverify |
| 7 | **设备指纹软限** | 自建 canvas/webgl hash + localStorage id，免费 | 同设备多开（弱一致，可伪造） | 半天 |
| 8 | **邀请码** | 免费 | 内测期完全可控 | 1 个字段 + 1 个开关 |
| 9 | 新账号额度收紧 | 免费 | 注册后薅模型 token | 配额表已有 |

**注意 Turnstile 的前置条件**：site key 要绑定域名，纯 IP 访问（`http://134.175.207.249`）不被接受。没有域名时用第 1–6 项就足够，别为了验证码去买服务。

推荐配置：

```properties
# 内测期：邀请码；公开期改成 open
PANEL_SIGNUP_MODE=invite
PANEL_SIGNUP_INVITE_CODE=<随机 12 位>

# 有域名后打开
PANEL_TURNSTILE_ENABLED=true
PANEL_TURNSTILE_SITE_KEY=<site key>
PANEL_TURNSTILE_SECRET=<secret key>

# 邮件（QQ 邮箱示例，密码填"授权码"不是登录密码）
PANEL_MAIL_HOST=smtp.qq.com
PANEL_MAIL_PORT=465
PANEL_MAIL_USERNAME=<你的QQ邮箱>
PANEL_MAIL_PASSWORD=<授权码>
PANEL_MAIL_FROM=Panel <你的QQ邮箱>
```

> 用自有域名发信务必配 SPF + DKIM（Brevo/Resend 后台给记录），否则验证码大面积进垃圾箱，用户直接流失。

语义（**代码必须严格按这个实现，否则隔离会漏**）：

| 值 | 含义 | 读 | 写 |
|---|---|---|---|
| `owner_user_id = N` | 用户 N 的私有数据 | 仅 N + 平台管理员 | 仅 N |
| `owner_user_id IS NULL`（简历/面试） | 历史数据 / 管理员导入 | 平台管理员 | 平台管理员 |
| `owner_user_id IS NULL`（题库） | **平台公共题库** | 所有登录用户只读 | 平台管理员 |

## 3. 数据隔离设计

### 3.1 统一闸门：`OwnershipGuard`

新增 `com.panel.shared.security.OwnershipGuard`，所有涉及个人数据的服务只用它判断，禁止各写各的。

```java
@Component
public class OwnershipGuard {

    private final CurrentActorProvider actors;

    public OwnershipGuard(CurrentActorProvider actors) {
        this.actors = actors;
    }

    public CurrentActor actor() {
        return actors.requireCurrent();
    }

    public Long currentUserId() {
        return actor().userId();
    }

    /** 平台管理员 / 管理员 = 运营视角，可看全量；其余只看自己。 */
    public boolean canSee(Long ownerUserId) {
        CurrentActor actor = actor();
        if (actor.isPlatformAdmin() || actor.roles().contains(RoleCode.ADMIN)) {
            return true;
        }
        return ownerUserId != null && ownerUserId.equals(actor.userId());
    }

    /**
     * 私人资源一律 404：403 会告诉攻击者"这个 id 存在但不属于你"，
     * 404 连存在性都不确认。公共资源权限不足才用 403。
     */
    public void requireVisible(Long ownerUserId) {
        if (!canSee(ownerUserId)) {
            throw new BusinessException(ErrorCode.RESOURCE_NOT_FOUND);
        }
    }

    public boolean isAdmin() {
        CurrentActor actor = actor();
        return actor.isPlatformAdmin() || actor.roles().contains(RoleCode.ADMIN);
    }
}
```

`KbAccessGuard` 补丁（全文替换核心两个方法）：

```java
public boolean canRead(KnowledgeBase base) {
    if (base == null) return false;
    CurrentActor actor = actors.current().orElse(null);
    if (actor == null) return false;
    if (actor.isPlatformAdmin() || actor.roles().contains(RoleCode.ADMIN)) return true;

    if (base.ownerUserId() == null) {
        // 平台公共库：PUBLIC 所有登录用户可读；INTERNAL 仍需内部角色
        return base.visibility() == KbVisibility.PUBLIC
                || actor.roles().stream().anyMatch(INTERNAL_ROLES::contains);
    }
    // 私有库：只有主人能读，连 403 都不给，直接 404
    return base.ownerUserId().equals(actor.userId());
}

public void ensureWritable(KnowledgeBase base) {
    CurrentActor actor = actors.current()
            .orElseThrow(() -> new BusinessException(ErrorCode.UNAUTHENTICATED));
    if (actor.isPlatformAdmin()) return;
    if (base.ownerUserId() == null) {
        throw new BusinessException(ErrorCode.FORBIDDEN, "内置题库只读");
    }
    if (!base.ownerUserId().equals(actor.userId())) {
        throw new BusinessException(ErrorCode.RESOURCE_NOT_FOUND);
    }
}

public void ensureReadable(KnowledgeBase base) {
    if (!canRead(base)) {
        // 私有库不给存在性，公共库给明确原因
        if (base != null && base.ownerUserId() != null) {
            throw new BusinessException(ErrorCode.RESOURCE_NOT_FOUND);
        }
        throw new BusinessException(ErrorCode.FORBIDDEN,
                "这个知识库仅内部可见：" + (base == null ? "" : base.name()));
    }
}
```

### 3.3 权限与角色的连带调整

`CANDIDATE` 现在没有 `menu:knowledge`，也就没有 `knowledge:write`，无法建自己的题库。有了 owner 隔离后，把 `knowledge:write` 给候选人是安全的：写入只会落在自己名下的库。

```java
// PermissionCatalog.defaults() 的 CANDIDATE
defaults.put(RoleCode.CANDIDATE, Set.of(
        "menu:dashboard", "menu:assistant", "menu:knowledge", "menu:resume",
        "menu:jobs", "menu:interviews", "menu:reports", "menu:profile"));
// roleMenuOperations() 的 CANDIDATE menu:knowledge
Map.entry("menu:knowledge", Set.of("knowledge:read", "knowledge:write", "ocr:use"))
```

前端对应把"知识库管理"对候选人显示为「我的题库」，隐藏"全站库"概念。

### 3.4 竞态与索引

- 去重：`(owner_user_id, content_hash)` 加**普通**索引即可，唯一索引在存量数据可能有重复时会迁移失败。真要强一致，先跑一遍重复扫描再改唯一。
- 两次并发上传同一文件 → 可能各插一行；这是可接受的重复，不要为它上表锁。
- `owner_user_id` 一律**可空**：迁移前老数据回填，回填失败仍是平台数据，不会让启动失败。

### 3.6 题库隔离后要回答的三个运营问题

1. **公共题库谁维护**：内置三个库（`question-bank` / `tech-knowledge` / `job-knowledge`）`owner_user_id` 保持 NULL，平台管理员上传，所有用户只读。用户"我的题库"同名不同 code，互不影响。
2. **面试信号回填**：`kb_skill_state` / `kb_skill_interview_import` 已按 `userId`，回填接口必须只允许 `userId == actor.userId()` 或管理员代跑，别再放开 `?userId=` 任意指定。
3. **统计看板**：覆盖率、薄弱知识点全部按用户；平台侧想看整体，走管理员专用接口，别让前端用同一套接口。

## 5. 容易踩的坑

1. **对象存储 key 里没有 userId**（`resume/<uuid>/<name>`）。隔离只能靠行级校验，所以「先取行、校验、再读对象」的顺序不能反，否则先是读文件再 404，等于白读。
2. **404 会让前端"详情页空白"**：路由拿到 404 要跳回列表并提示"记录不存在或已删除"，不要显示成网络错误。
3. **管理员视角会被前端当成 bug**：管理员看到全部简历是设计，但列表要标出归属人，否则运营会误操作。
4. **`/auth/register` 不关掉等于开了个"自助当管理员"的后门**：它创建的是 `ADMIN` 租户。
5. **邮箱验证码别写进日志**：`GlobalExceptionHandler` 与 `TraceIdFilter` 都会打请求体，含 `password` / `code` 的字段要在日志层打码。
6. **个人租户会让租户数量线性增长**：`sys_tenant` 一万行没问题，但任何"遍历所有租户"的定时任务要加索引与分页。
7. **别删 `created_by`**：`kb_base.created_by` 与新的 `owner_user_id` 语义不同（操作人 vs 归属人），后台改归属时两者都要改。
