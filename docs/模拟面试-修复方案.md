## 阶段一：P0 正确性与出口

### F1 三段式事务 + turn 状态机

**现状**：`InterviewService.answer` 标了 `@Transactional`，方法体里跑了评分（2 次模型）、
出题（1 次模型），最后一题还跑报告（1 次模型）。异常 → 全部回滚 → `turn.answer()` 一起没了。

**改法**：把"写库"拆成三个短事务，模型调用一律放在事务外。新增应用层类
`InterviewTurnService`（只做短事务，不碰模型）：

```java
@Service
public class InterviewTurnService {

    /** ① 认领这道题并把答案落库（毫秒级）。重复提交在这里被拦下。 */
    @Transactional
    public Claim claim(Long sessionId, String answerText) { ... }

    /** ② 落评分结果（毫秒级）。finalScore 为 null 表示本轮未评分。 */
    @Transactional
    public void saveEvaluation(long turnId, String scoresJson, Integer finalScore,
                               String feedback, String reviewJson) { ... }

    /** ③ 开下一题 + 推进 currentTurn（毫秒级）。 */
    @Transactional
    public InterviewTurn openNext(long sessionId, int seq, NextTurn spec) { ... }

    /** ③' 收尾：写报告 + 总分。 */
    @Transactional
    public void complete(long sessionId, String reportJson, int overallScore) { ... }

    /** 卡在 GRADING 超过 2 分钟：判为未评分，允许前进。 */
    @Transactional
    public boolean releaseStaleGrading(long sessionId) { ... }
}
```

`Claim` 是一次性的只读快照，让事务外的那段逻辑不需要再查库：

```java
public record Claim(long turnId, int seq, String kind, String question, String skill,
                    String pointId, int depth, String answer,
                    Long sessionId, int questionCount, int followUpLimit, int followUpThreshold,
                    List<InterviewTurn> answered, InterviewPlan plan, int answeredMains) { }
```

`answer()` 变成：

```java
public AnswerResult answer(Long sessionId, String answerText, InterviewProgressListener listener) {
    if (answerText == null || answerText.isBlank()) {
        throw new BusinessException(ErrorCode.VALIDATION_FAILED);
    }
    Claim claim = gate.claim(sessionId, answerText.trim());          // ① 事务（认领）
    JudgePanel panel = judge(claim, listener);                        // 事务外，带预算（F2）
    ReviewDecision review = suspicious(panel.technical(), claim.answer())
            ? reviewer.review(claim.question(), claim.answer(), panel.technical()) : null;
    int score = applyReview(panel.technical(), review);
    gate.saveEvaluation(claim.turnId(), EvaluationJson.write(objectMapper, panel.technical(), panel.expression()),
            score, feedbackOf(panel.technical(), review), review == null ? null : write(review));   // ② 事务
    Step step = InterviewFlowPolicy.decide(...);                      // 纯函数，不碰库
    return switch (step) {                                            // 模型在事务外，写库再开短事务
        case FOLLOW_UP -> advanceWith(claim, () -> interviewer.followUp(...));   // ③
        case NEXT_MAIN -> advanceWith(claim, () -> interviewer.next(claim.plan(), claim.answered())); // ③
        case FINISH -> finishSession(claim, listener);                // ③'
    };
}
```

**`InterviewTurn` 增加状态列**（迁移 `V8__interview_turn_state.sql`）：

```sql
ALTER TABLE `interview_turn`
  ADD COLUMN `turn_state` varchar(16) COLLATE utf8mb4_unicode_ci NOT NULL DEFAULT 'ASKED',
  ADD COLUMN `grading_started_at` datetime(6) DEFAULT NULL;

-- 存量数据：有答案的视为已答完，没答案的视为待答
UPDATE `interview_turn`
   SET `turn_state` = CASE WHEN `answer` IS NULL THEN 'ASKED' ELSE 'ANSWERED' END;

ALTER TABLE `interview_turn` ADD KEY `idx_turn_state` (`session_id`, `turn_state`);
```

实体侧：`markGrading()`（写 `grading_started_at`）、`evaluated(...)` 里置 `ANSWERED`、
`markUnscored(String note)` 置 `UNSCORED`。`ddl-auto: validate`，字段名必须和迁移一致。

**测试**
- `InterviewTurnTest`（纯 POJO）：`ask → answer → markGrading → evaluated` 的状态迁移；`answer()` 之后不能再次 `answer()`。
- `InterviewTurnServiceTest`（Mockito，不需要 Spring 上下文）：无 pending 题 → `CONFLICT`；pending 题状态 `GRADING`；`releaseStaleGrading` 只放行超时的。
- `InterviewServiceTest`：`evaluator` 抛异常时，`gate.saveEvaluation` 从未被调用，且 `claim` 已提交（用 `InOrder` 断言顺序）；答案文本在 claim 之后不再依赖请求作用域。

**验收**：把 evaluator 的模型地址改成不可达 → 提交回答 → 接口返回错误，但刷新页面后该题 `answer` 仍在（不再丢话）。

### F2 每轮预算与降级

**现状**：`await(future)` 无超时，靠 HTTP 30s 兜底；两次调用串起来 60s+。

**改法**：`InterviewService` 加预算常量，所有等待都按剩余时间取：

```java
private static final Duration TURN_BUDGET = Duration.ofSeconds(45);

private JudgePanel judge(Claim claim, InterviewProgressListener listener) {
    Instant deadline = Instant.now().plus(TURN_BUDGET);
    ...
    TurnEvaluation judged = await(technical, deadline);       // 超时 → 抛 TurnTimeoutException
    TurnEvaluation second = awaitOrNull(expression, deadline);
}

private static <T> T await(Future<T> future, Instant deadline) {
    try {
        return future.get(Math.max(1, Duration.between(Instant.now(), deadline).toMillis()),
                TimeUnit.MILLISECONDS);
    } catch (TimeoutException ex) {
        future.cancel(true);
        throw new TurnTimeoutException("本轮评审超时");
    }
    ...
}
```

`answer()` 里捕获 `TurnTimeoutException`：**答案已经落库**，本轮按"未评分"收尾，
不追问、直接推进下一题：

```java
} catch (TurnTimeoutException timeout) {
    gate.saveEvaluation(claim.turnId(), null, null, "本题评审超时，未计入总分", null);
    // scored=false 时 policy 不追问，直接按配额决定换题或收尾
    step = InterviewFlowPolicy.decide(false /*opening*/, 0, threshold, depth, limit, answeredMains, count, false /*scored*/);
}
```

`InterviewFlowPolicy.decide` 增加 `boolean scored` 参数（`scored=false` → `mayFollowUp=false`），
顺势补两条测试（未评分不追问、未评分仍能收尾）。

**验收**：用 `--panel.ai.chat.slow=true`（或在网关上加 50s 延迟）模拟慢模型 → 45s 后前端收到 `question` 事件，本轮分数为"未评分"，报告里该题标注。

### F3 `advance` / `finish`：给中间态一个出口

**契约**

```
POST /api/v1/interview/sessions/{id}/advance     权限 interview:answer
  200 { status, nextQuestion | null, overallScore | null, report | null }
  · 已有待答题        → 原样返回该题（幂等，不重复生成）
  · 无待答题、有已评分题 → 按 policy 决定：追问 / 换题 / 收尾
  · 卡在 GRADING 超 2 分钟 → 先 releaseStaleGrading 再推进
  · 已 COMPLETED      → 返回 report
  · PLANNED / FAILED  → 409

POST /api/v1/interview/sessions/{id}/finish      权限 interview:answer
  200 report payload（提前结束：用已答题生成报告，一题没答则 overall=null）
```

**后端点**：`InterviewController` 两个方法直接复用 `InterviewService.advance(id)` /
`InterviewService.finishEarly(id)`，都用现有的 `stream(...)` 包一层（前端照旧看 agent 进度）。

**前端恢复**（`InterviewPage.tsx`）：

```tsx
const stuck = session.status === 'IN_PROGRESS' && !pendingTurn
useEffect(() => {
  if (!stuck || busy) return
  void resume()          // 先自动试一次 advance，失败才显示按钮
}, [stuck])

// 顶部提示条 + 底部按钮
{stuck && (
  <button onClick={() => void speakAndAdvance()}>
    {resumeFailed ? '继续面试（重新出题）' : '正在接上进度…'}
  </button>
)}
```

同时在页面右侧「记录」按钮旁边加一个 `结束面试`（调 `finish`），把"面试可以提前结束"
这个真实场景补上——现在只能答完 N 题，或者干脆丢弃会话。

**测试**
- `InterviewServiceTest#advanceIsIdempotent`：有 pending 题时连续两次 `advance` 返回同一个 seq，且 `interviewer.next` 只被调 0 次。
- `InterviewServiceTest#advanceReleasesStaleGrading`：turn 处于 `GRADING` 且 `grading_started_at` 是 3 分钟前 → 推进成功。
- `InterviewServiceTest#finishEarlyWithoutAnswers`：只有开场题 → 报告 `overallScore = null`，`summary` 说明未作答。

**验收**：面试进行到第 3 题时 `kill` 后端 → 重启 → 页面自动接上并继续（不刷新也能在 40s 内恢复）。

### F4 一个主问题 → 总分 0

两处一起改：
1. 后端 `clampQuestions` 下限改 2（`MIN_QUESTIONS = 2`），语义仍是"总题数含开场"；
2. 前端 setup 滑块 `min={2}`，并在 `stats.points < 2` 时提示"这份简历的批注点太少，至少需要 2 个"。

`finish()` 的总分算法加空集兜底：

```java
List<Integer> scored = answered.stream()
        .filter(t -> !KIND_OPENING.equals(t.getKind()))
        .map(InterviewTurn::getFinalScore).filter(Objects::nonNull).toList();
if (scored.isEmpty()) {
    // 只有开场题（老会话 / 用户强行结束）：宁可把开场题计入，也不要给 0 分
    scored = answered.stream().map(InterviewTurn::getFinalScore).filter(Objects::nonNull).toList();
}
```

**测试**：`InterviewFlowPolicyTest` 已有 7 条；新增 `InterviewServiceTest#oneQuestionStillScored`。

### F5 幂等认领

```java
// SpringDataInterviewTurnRepository
@Lock(LockModeType.PESSIMISTIC_WRITE)
@Query("select t from InterviewTurn t where t.sessionId = :sessionId and t.turnState = 'ASKED' order by t.seq asc")
Optional<InterviewTurn> lockPending(@Param("sessionId") Long sessionId);
```

`claim()` 用 `lockPending`：拿不到 → `BusinessException(ErrorCode.CONFLICT)`，并把当前题
一起返回（新增 `ConflictWithQuestion` 或者在 error payload 里带 `nextQuestion`），
前端据此把界面刷成"这道题已经在评审中"而不是弹一句"提交失败"。

同时把 `DataIntegrityViolationException`（`uk_session_seq`）映射成 `CONFLICT`，
避免偶发并发直接 500。

**测试**：两个线程同时 `claim` 同一 session → 一个成功、一个 `CONFLICT`。

## 阶段二：P1 时延

### F6 预生成并行（+ 追问复用预生成草稿）

**现状**：评分（3-8s）→ 出题（3-6s）串行。

**改法**：在 `judge()` 起跑的同时，把两套可能的下一步都先算出来，用 policy 的结果二选一：

```java
Instant deadline = Instant.now().plus(TURN_BUDGET);
Future<TurnEvaluation> technical  = executor.submit(wrap(() -> evaluator.evaluate(...)));
Future<TurnEvaluation> expression = executor.submit(wrap(() -> expressionJudge.evaluate(...)));
Future<QuestionDraft>  nextDraft  = speculative
        ? executor.submit(wrap(() -> interviewer.next(claim.plan(), claim.answered())))
        : null;
Future<QuestionDraft>  followDraft = speculative
        ? executor.submit(wrap(() -> interviewer.followUp(point, chain, claim.answer())))
        : null;
```

开关：`panel.interview.speculative-draft`（默认 `true`）。代价是每轮多 1 次出题调用
（约 1500 token），换来 3-6 秒。若 `followDraft` 失败或 policy 没选它，直接丢弃——
出题本来就是"可重试、可兜底"的（`InterviewerAgent` 已有重试 + 规则兜底题）。

**顺手把 `followUps` 用起来**：`InterviewerAgent.next` 的 prompt 现在写死
`"followUps":[]`，改成要求给 2 条备用追问并落库；`askFollowUp` 先看当前题有没有未用的
备用追问，有就直接用（O 次模型调用）。只有备用追问不合适（已问过、或答案明显跑题）才走模型。

**验收**：`AgentEvent.durationMs` 里"答完→question 事件"P95 ≤ 7s。

### F8 直接用 `done` 载荷

`AnswerResult` 已经带了 `evaluatedTurn` / `nextQuestion` / `status` / `overallScore` / `report`，
前端本地合并即可，删掉每轮那次 `detail()`：

```ts
if (type === 'done') {
  const result = data as InterviewAnswerResult
  setSession(prev => prev && ({
    ...prev,
    status: result.status,
    overallScore: result.overallScore,
    turns: [...prev.turns.map(t => t.seq === result.evaluatedTurn.seq ? result.evaluatedTurn : t),
            ...(result.nextQuestion ? [asPendingTurn(result.nextQuestion)] : [])]
  }))
}
```

`detail()` 只保留在首屏进入和 `advance` 恢复时。

### F9 SSE 可取消 + 超时

`api/interview.ts` 的 `sse()` 加 `signal` 与超时：

```ts
async function sse(path, body, onEvent, options: { signal?: AbortSignal; timeoutMs?: number } = {}) {
  const controller = new AbortController()
  const timer = window.setTimeout(() => controller.abort(new Error('timeout')), options.timeoutMs ?? 90_000)
  options.signal?.addEventListener('abort', () => controller.abort())
  ...
}
```

页面侧：`submit()` 保存 controller，`useEffect` 卸载时 abort；提交中把发送按钮换成
「取消」（abort 之后调 `advance` 把会话接回去，正好复用 F3）。

## 阶段三：P2/P3

### F10 计时 / 草稿 / 重听

- `elapsed` 改成由 `session.createdAt` 推导：`Math.floor((Date.now() - Date.parse(createdAt)) / 1000)`，
  刷新不再归零；
- 草稿按 `sessionId` 存 `sessionStorage`（`key = interview:draft:{id}`），提交成功后清；
- `useInterviewerSpeech` 暴露 `replay()`（用上次的 `turnSeq` 再 `speak` 一次，命中内存 buffer），
  题目下方加「重听」按钮。

### F11 移动端

- `< md` 用竖排布局：题目在顶部、人像缩成 96px 头像、作答条正常流式布局、摄像头画中画收进顶栏；
- 录音从"按住"改成"点一下开始/再点结束"（`usePushToTalk` 已有 `start/stop`，加一个 `toggleMode`），
  `md` 以下默认点按式；VAD（静音 800ms 自动 `finish`）放到后续迭代。

### F12 表达评委降级标注

`TurnEvaluationPanel` 里判断 `evaluation.judges?.expression == null` → 显示
「本轮表达视角未评（已降级为单评委）」；报告页顶部汇总"共 N 轮单评委"，让降级可见。

### F13 用量账 / 配额 / 指标

- **记账**：`AsrWebSocketHandler` 与 `AgentUsageRecorder` 都跳过"无 tenantId"的 actor →
  建议 Flyway 加一个 `system` 租户，或放开 `ai_usage_record.tenant_id` 非空约束（改实体 + 迁移），
  让 platform actor 也能落账；
- **配额**：`InterviewQuotaService`（仿 `AsrQuotaService`）：每日场次、每日模型调用次数；
  超限时 `InterviewController` 返回 429，前端提示"今天的面试额度用完了"；
- **指标**：`AgentEvent` 已经有 `durationMs`——在 `InterviewProgressListener` 的实现里落
  Micrometer `Timer`（tag: agent）与失败 `Counter`，`/actuator/metrics` 就能看 P95。

### F14 题面与人像的纵向互斥

**现象**：题面居中压在画面上三分之一，人像位置是常数 `top-[35%]`。题面高度由"这一题多少字"
决定——真实题库里开场 114 字、主问题 130~280 字、叠了上下文的追问到过 434 字。
4 行往上题面就骑到发顶，`实战经验 · ADVANCED` 那行直接横穿额头。

**改法**（`InterviewPage.tsx` + `DigitalInterviewer.tsx`）：

1. 舞台改成一列纵向流：`[题面 auto] → [人像 flex-1]`。题面按内容长，人像只吃剩下的高度，
   顶边由 `top-7`（28px）钉在题面底边下面。**重叠在结构上不可能发生**，不依赖 JS 量高度——
   手算的常数（包括"更保守的 35%"）都会被换行差异打破，上一版就是这么坏的。
2. 题面按字数分档：≤60 字 30/26px，≤120 字 27/24px，≤200 字 24/22px，再多 22/20px。
   长题先缩字号，而不是先挤人像。
3. 题面给高度上限 `min(44vh, 340px)`，超了在自己的区域里滚，底部渐隐 + meta 行加
   「题面较长，滚动可看全文」。人像因此永远留得住脸。
4. 人像不给最小高度：矮屏上撑大会把下巴推进作答条里，而脸是这张图唯一不能裁的部分。
   方图下沿仍然探进作答条后面（`bottom-20`，矮屏 `bottom-16`），把素材在 84.2% 处
   被裁断的那条直线藏在卡片后面。

**顺带修根因**：出题/追问提示词都加了「70 字以内」，`InterviewerAgent` 的 INSTRUCTION 第 9 条
与 FOLLOW_UP 第 6 条——题面长度不该由前端硬扛。

**验收**：1440×900 / 1280×800 / 1024×768 三档，题面 114 / 256 / 420 / 600 字四种长度，
`meta` 底边到发顶的间距都应 > 20px，作答条不压嘴。探针见 `tmp/probe/layout-probe.cjs`。

## 风险与回滚

- **迁移**：`V8` 只加列加索引 + 一次 `UPDATE`，可回滚（`ALTER TABLE ... DROP COLUMN`），
  但 Flyway 不自动回滚——发布前在预发库跑一遍 `flyway:info`/`migrate` 确认校验和。
- **事务拆分**：把原来"一次原子提交"变成"两次提交"，中间态（已评分但无下一题）由 F3 覆盖。
  上线顺序必须是 **F3 先于 F1**，否则拆事务会新增一类卡死。
- **预生成开关**：`panel.interview.speculative-draft=false` 即可整体退回串行（行为与今天一致）。
- **TTS 预合成**：`SpeechService.warm()` 另起虚拟线程，失败只打日志；`panel.ai.speech.enabled=false`
  时直接 no-op，不影响面试。
